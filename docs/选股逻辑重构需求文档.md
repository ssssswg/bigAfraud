# 选股逻辑重构需求文档

## 1. 背景与痛点

当前选股系统的核心问题：

- **选股过多、无法抉择**：每日执行选股会命中大量股票（一次可达 90+ 只），累计后候选池越来越大，用户难以从众多候选中决定买入哪一只。
- **单日信号不足以判断趋势**：策略命中基于当日/几日信号，但**一天的走势不能代表短中期趋势**。当前系统只产出"当天入选"的候选，缺少对命中后持续表现（观察期）的跟踪与验证，导致大量"一次性信号、次日走弱"的股票占据候选池。
- **缺少"持有 vs 切换"决策**：系统不记录策略的历史最强候选，无法回答"这只策略现在是继续持有旧的最佳标的，还是切换更新更强的"。

## 2. 需求目标

重构选股逻辑，从「每日广撒网产出大量候选」变为「**每个策略维护一个当前最强标的（持有标的），通过观察期验证 + 强弱对比，产出确定性的持有/切换建议**」。

- 每个策略最终**最多推荐 1 只**确定的持有标的（而非每日一堆）。
- 对命中策略的股票设置**观察期**（按策略短/中/长线分类），观察期内持续跟踪，**超过观察期仍不符合预期则舍弃**，重新选择。
- 系统**持久记录**每个策略的历史最强标的与其评分，支持「新候选 vs 当前持有」的强弱对比决策。

## 3. 术语定义

| 术语 | 定义 |
|---|---|
| 投资周期 | 策略的持有周期类型：短线 / 中线 / 长线 |
| 观察期 | 标的命中策略后进入的跟踪窗口（交易日数），短/中/长线策略不同 |
| 持有标的 | 某策略当前选定、正在跟踪的最强标的（每个策略 0~1 只） |
| 标的强度 | 用于对比新旧标的的量化分数（基于综合评分、趋势强度、涨幅等） |
| 切换 | 新候选强度 > 当前持有标的强度时，替换持有标的 |
| 舍弃 | 持有标的观察期超期且不符合预期，放弃该标的，重新选新 |

## 4. 功能需求

### FR1 策略投资周期分类
- 对全部选股策略标注投资周期：`short`（短线）/ `mid`（中线）/ `long`（长线）。
- 分类基于策略逻辑定位（见 8.1 初始分类表），**可配置、可评审调整**。
- 配置存放于 `config/strategy_params.yaml`，每个策略新增 `investment_horizon` 与 `observe_period_days` 字段。

### FR2 观察期机制
- 标的命中策略后进入观察期，观察期长度按策略投资周期：
  - 短线：默认 5 个交易日
  - 中线：默认 20 个交易日
  - 长线：默认 40 个交易日
- 观察期内每日跟踪持有标的表现（K线、评分、趋势）。
- **观察期判定**：自标的"命中日期"起，累计 K 线交易日数达到观察期上限时，判定观察期结束。
- **舍弃规则**：观察期结束时，若持有标的仍不符合预期（如未达到预期收益、趋势走弱、跌破关键支撑），则**舍弃**该标的，从当日/近期新候选中重新选择最强标的作为持有标的。
- 观察期内若标的触发卖出信号（跌破 MA5/MA10、放量滞涨等，复用现有卖出逻辑），视为不符合预期，可提前舍弃。

### FR3 历史持有标的持久化
- 新建数据表 `strategy_hold_record`，持久记录每个策略的持有状态：
  - 当前持有标的：stock_code、stock_name、命中日期、观察期截止日、强度评分、状态（观察中/已确认持有/已舍弃）。
  - **历史最强记录**：系统记录该策略历史所有被评估过的标的及其评分，用于「最早的股票和对应评分」的追溯。
- 保证进程重启后持有状态不丢失。

### FR4 强弱对比与持有/切换决策
- 每次选股（每日）后，对每个策略执行如下决策：
  1. **无持有标的**：从当天新选出的候选中，选**强度最高**的 1 只作为持有标的（若当天无候选，保持空）。
  2. **有持有标的**：
     - 计算当天新候选的**最高强度** `S_new` 与当前持有标的强度 `S_hold`。
     - 若 `S_new > S_hold`（且新候选在观察期内仍符合预期）→ **切换**：推荐持有新标的。
     - 否则 → **继续持有**当前标的。
  3. **观察期超期且不符合预期**：舍弃当前持有标的，重新选最强新候选。
- 决策结果以「建议」形式输出（继续持有 / 切换至新标的 / 空仓等待），并记录原因。

### FR5 强度评分口径
- 标的强度 `S` = 综合评分 `score`（0~100，复用现有 `score_calculator`）。
- 可选增强因子（后续迭代）：趋势强度、相对强度（RS）、距观察期收益率。
- 初始版本以 `score` 为唯一强度口径，保证可比性。

### FR6 输出与展示
- 选股结果按策略聚合输出，每个策略至多 1 只**推荐标的**，展示：
  - 持有标的（代码、名称、命中日期、观察期截止、强度、状态）
  - 决策建议（继续持有 / 切换 / 空仓）与原因
- 前端「选股排名/选股结果」页面展示上述信息。

## 5. 非功能需求

| 编号 | 需求 |
|---|---|
| NFR1 | 兼容性：不破坏现有策略执行与评分逻辑；现有 `stock_selection_record` 表保留 |
| NFR2 | 性能：持有决策在选股完成后增量执行，不额外拉取全市场数据 |
| NFR3 | 可配置：投资周期、观察期、强度阈值均可在配置中调整 |
| NFR4 | 可追溯：持有状态与历史记录持久化，可查询任一策略任一标的的历史评分 |
| NFR5 | 并发安全：持有记录写入走统一写锁（复用 db_manager 锁体系） |

## 6. 数据模型

### 6.1 新增表 `strategy_hold_record`

| 字段 | 类型 | 说明 |
|---|---|---|

| strategy_name | VARCHAR(100) | 策略名称（中文/英文均可，与记录一致） |
| stock_code | VARCHAR(20) | 当前持有标的代码 |

| updated_at | DATETIME | 更新时间 |
| UNIQUE(strategy_name) | | 每策略至多一条当前持有 |

| 字段 | 类型 | 说明 |

### 6.3 配置扩展 `config/strategy_params.yaml`


## 7. 核心流程

### 7.1 每日选股 → 持有决策流程

```
每日触发选股
   ↓
对每个策略执行选股 + 评分（复用现有 _select_and_score_stocks）
   ↓
对每个策略：
  ├─ 无持有标的 → 取当天强度最高候选为持有标的（进入观察期）
  ├─ 有持有标的 →
  │    计算 S_new（当天候选最高强度） vs S_hold（当前持有强度）
  │    S_new > S_hold → 切换持有至新标的
  │    S_new <= S_hold → 继续持有
  └─ 观察期超期且不符合预期 → 舍弃持有标的，重新选
   ↓
输出：每策略 0~1 只推荐标的 + 决策建议
```

### 7.2 观察期跟踪

```
持有标的在观察期内（hit_date ~ observe_end_date）：
  每日校验：
  - 触发卖出信号（破位/滞涨）→ 提前舍弃
  - 观察期截止且收益/强度不达标 → 舍弃
  - 否则 → 继续持有，更新强度评分
```

## 9. 验收标准

- AC1：每个策略均有 `investment_horizon` 与 `observe_period_days` 配置，短/中/长分类正确。
- AC2：策略命中后进入观察期，观察期长度符合投资周期。
- AC3：持有标的持久化，重启后状态不丢失；历史最强标的与评分可追溯。
- AC4：强弱对比决策正确——新候选强则切换、旧持有强则继续持有、观察期超期不符合预期则舍弃。
- AC5：每个策略最终输出 0~1 只推荐标的，不再每日堆积大量候选。
- AC6：不影响现有选股/评分/回测功能，全流程无异常。

## 10. 风险与待确认

- **强度口径**：初始仅用 `score`，后续可引入趋势强度/RS/观察期收益多维强度。
- **观察期数值**：短线 5/中线 20/长线 40 为初始默认，需结合历史回测校准。
- **策略分类**：8.1 为基于规格说明的初始建议，需与策略作者/历史表现评审后定稿。
- **与现有卖出逻辑的衔接**：提前舍弃复用现有卖出信号（跌破MA5/MA10、放量滞涨）。

### 已实现
- **核心模块** `utils/strategy_hold_manager.py`：策略周期分类、观察期机制、持有/切换/舍弃决策、`strategy_hold_record` + `strategy_hold_history` 持久化、强度对比（综合评分）。
- **配置**：`config/strategy_params.yaml` 新增顶层 `strategy_hold` 段（horizon / observe_period_days / abandon_score_threshold），可调；模块内置默认分类兜底。
- **接入**：`web_server.py` 的 `run_selection` 在选股完成后对每个策略执行持有决策，把推荐标的（含 hold_action / hold_reason / horizon）写回结果返回前端。

### 验证结果
- 单元用例（临时库）：
  - 首选中 `new` ✓；新候选更强 `switch` ✓；新候选更弱/同分 `hold`（继续持有旧）✓
  - 无候选无持有 `empty` ✓；无候选有持有 `hold` ✓
  - 观察期超期 + 评分不达标 → `discard` 舍弃（有新候选则切换，无则空仓）✓
  - 观察期超期 + 达标 → `holding` 确认持有 ✓
  - 历史记录（selected / replaced / discarded）正确落库 ✓
- 配置读取：20 策略分类、观察期短5/中20/长40、阈值60 正确加载 ✓
- 建表：`strategy_hold_record` / `strategy_hold_history` 自动创建 ✓
- 全量 py_compile 通过 ✓
